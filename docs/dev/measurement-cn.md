# 从原型照片测量刻度

这是把原型照片变成驱动绘制的实测表所用的方法。它的目的是**可追溯**：每个区间、
步长、档级和印数都必须来自照片（或维基），绝不来自猜测。

## 照片

`docs/domain/prototype/` 下有 `1002-front.jpg`、`1002-back.jpg`、`57-front.jpg`
和 `57-back.jpg`。它们是刻度布局的唯一来源。三个性质决定了方法：

- **梯形畸变（keystone）**：正面照片自左向右比例缩小（左侧约 3000 px/十进制，
  右侧约 2840），所以"像素→位置"用直线不够准。
- **轻微旋转**：尺身并非完全水平，一行的基线在整幅画面里会漂移几个像素。
- **光照不均与 JPEG 模糊**：区分墨与纸的阈值逐区域变化，最细的刻度有时只有
  两个像素宽。

## 工具

照片用 `jpeg-js` 无损解码。当像素亮度 `0.299 R + 0.587 G + 0.114 B` 低于阈值
（默认 150，按区域调整）时判为**暗**。脚本位于
[`tools/measure/`](../../tools/measure/README.md)，它们只离线使用，不参与构建。

## 1. 定位该行

`strip.js` 把一块区域按"一像素一字符"打印成二值 ASCII，能直接看清基线
（刻度所依附的那条边）及其斜率。记下刻度是自**下**基线**向上**伸，还是自**上**
基线**向下**垂；并原样抄下该行印的名称。

## 2. 提取刻度

`rowscan.js` 逐像素列扫描该行：在基线附近几个像素内找第一个暗像素，量出暗条
延伸多远，再把相邻列并成一个刻度（中心 `x`、宽度、长度）。基线取
`yBase + slope*(x-465)`，由此把梯形畸变和旋转都吸收进 `slope`。

真正的刻度又窄又孤立：宽度集中在 2–5 像素。过宽的团块是阴影、定尺与动尺之间的
凹槽、或邻行渗墨，通过查看 ASCII 条带予以剔除。

## 3. 标定"像素→位置"

印出的值 `v` 决定了理论**位置** `p`，单位为 C/D 十进制（`0..1` 即 C/D 范围）：

```
p = log10(fn(v) / ref)
```

`fn` 是该标尺自身的函数（C/D 是恒等、sin2 是正弦、th2 是双曲正切……），`ref`
使得该十进制对齐。每个印数都压在它中心附近最长的刻度上，因此一个印数给出一对
锚点 `(x, p)`。

`fitmap.js` 用这些锚点拟合低次多项式。**平放的背面**照片只需直线
`x = A + B p`；**有梯形畸变的正面**需要二次或三次
`p = c0 + c1 x + c2 x^2 ...`。残差在几个像素以内即认为拟合可用；残差偏大说明
锚点取值有误。

## 4. 读出数值与步长

每个刻度的 `x` 经拟合换算为 `p`，再经 `fn` 反解得到数值。按位置排序后，一段内
相邻刻度的**中位间隔**就是该段最细的步长；两个印数之间的刻度数可作校验
（`(b - a) / step + 1` 个刻度）。

## 5. 判定档级

刻度**长度**聚成若干档：最长的一档是 1 级，其次 2 级，最短的是 3 级。长度阈值
随照片而异（`segments.js --lencuts`）。

从照片得到的一条教训是：**印数不一定是那条最长的刻度**。C 上 `1.05` 与 `1.1`
一样长，th2 上最长的刻度还会随分段变化。因此印数所在档级以照片所示为准，**不得**
把印数强制定为 1 级。

## 6. 分段

凡步长或档级规律发生变化处，就把该行拆成区间，每段记作 `[from, to)` 及其
`步长@档级` 列表。`segments.js` 会打印出这样一张初表。

## 7. 校验

结果用三种方式核对：

1. 把检出的刻度**叠加**回照片（`crop.js` 放大，或画出 `xc` 标记），逐条确认
   刻度数与档级。
2. 与自动生成的审计表（[`graduations.md`](graduations.md)，由 `npm test` 重写）
   对照。
3. 把软件的绘制与照片并排对照。

## 已知限制

- 约小于一个像素的步长无法分辨（例如 `sin2 [80,90]`）。
- 游标或工具栏的阴影会遮住某行的刻度（`th2` 尾段）。
- `th2` 分段的长档规律尚未确定。
- 渲染器默认的行带与普通行刻度在纸上"贴哪条边"可能不一致；这被记为待决问题，
  不作假设。
